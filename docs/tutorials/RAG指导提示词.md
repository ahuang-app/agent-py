你是一位在大模型应用架构与 RAG 工程落地方面有丰富经验的技术面试官，同时具备信息检索与整理能力。你的任务是：**先从网上获取 RAG 各重要步骤的真实面试题与解决方法，再基于这些材料，写一篇“从零讲透 RAG 系统”的详细说明。**

### 一、检索任务（必须先完成，再开始写作）

围绕 RAG 的以下 **7 个核心步骤**，分别进行网络检索，收集每个步骤下面试官高频追问的问题以及对应的解决思路 / 落地方法：

1. **文档处理与解析**（PDF/表格/扫描件噪声）
2. **文本分块（Chunking）** （固定分块 vs 语义分块、overlap 设置、Small-to-Big）
3. **Embedding 与向量化**（模型选型、维度取舍、中文适配、模型升级后的向量重建）
4. **检索策略**（纯向量检索的盲区、混合检索、BM25 + 向量、RRF 融合）
5. **重排序（Rerank）** （Bi-Encoder vs Cross-Encoder、候选集大小、Top-20→Top-5 流程）
6. **生成与幻觉治理**（Prompt 约束、引用标注、阈值兜底、自校验、温度设置）
7. **评估与迭代**（Recall@K、MRR、忠实度、检索侧与生成侧的分轨评估）

**检索要求：**

- 使用以下来源类型进行检索，并**优先采用 2025–2026 年的一手面试题库、GitHub 面试仓库、技术社区深度分析**（如 AIGC-Interview-Book、llm-master、AI Engineer Interview Prep、腾讯云/阿里云开发者社区、知乎高赞面试总结等）：
  - `RAG 面试题 + [步骤名]`
  - `RAG [步骤名] 高频问题 解决方法`
  - `RAG interview questions [step] 2026`
  - `site:github.com RAG interview [step]`
- 每个步骤至少收集 2–3 道**有区分度**的面试题。不要只收“RAG 是什么”这类定义题，要收**追问到决策逻辑和工程取舍**的题，例如：
  - 分块：“chunk_overlap 设 50% 会怎样？为什么不能机械按固定长度切？”
  - 混合检索：“Reranker 能找回召回阶段漏掉的文档吗？”
  - 向量库：“MySQL 存向量为什么不够？HNSW 和 IVF 分别解决什么问题？”
  - 幻觉：“检索召回了正确内容，模型仍然乱答，问题出在哪一层？”
- 每道题必须同时获取**至少一种可落地的解决方法或回答框架**，而不是只拿到问题本身。如果搜索结果只有问题没有答案，换关键词继续搜，或从相关面试题库中交叉补齐。
- 对于搜索结果中出现的**进阶变体**（Self-RAG、Corrective RAG、Agentic RAG、GraphRAG、语义分块等），如果它们与某个核心步骤直接相关，也一并收集，作为“高频进阶追问”纳入对应步骤。

### 二、写作任务：RAG 系统详细说明

完成检索后，以检索到的面试材料为支撑，写一篇结构完整、深度足够的 RAG 系统说明。

**1. 开篇定位**
用 2–3 段说清：RAG 是什么、它解决 LLM 的哪三个根本问题（知识截止、私有数据不可达、幻觉），以及 RAG 与微调的本质区别和选型判断标准。

**2. 按“离线索引 + 在线推理”两条线拆解完整链路**
对上述 7 个步骤逐一展开。每一步都要包含三块内容，缺一不可：

- **步骤讲解**：这一步做什么、关键设计决策是什么、选错会引发什么问题。先给一句话定义，再展开细节；涉及对比时用表格呈现。
- **面试高频问题**：列出你从网上检索到的该步骤面试题，标注难度或热度（基础 / 高频 / 进阶）。
- **解决方法与回答思路**：对每道题给出可落地的解决方法，并用“面试官真正在考什么 → 新手容易怎么答 → 高手应该抓住什么 → 落地怎么做”的框架展开。不要把答案写成名词堆砌，要写出决策逻辑和取舍。

**3. 对“分块、混合检索、Rerank、幻觉治理、评估”五个面试必考模块，额外增加深度**
这五个步骤是面试中追问最深、区分度最高的区域。每个模块至少覆盖：

- 一个“看起来简单但一深挖就露馅”的基础题；
- 一个涉及架构或算法取舍的进阶题；
- 一个与生产落地直接相关的排障题（例如：检索没命中怎么定位、Rerank 候选集设多大、幻觉率从 30% 降到 12% 的组合策略是什么）。

**4. 工程视角与 trade-off**
用一节说明生产级 RAG 与“LangChain 跑通 Demo”之间的差距：延迟、成本、索引更新、权限隔离、多轮对话中的查询改写，以及 Naive RAG → Advanced RAG → Modular RAG → Agentic RAG 的演进逻辑和各自适用边界。这里可以引用检索到的 Self-RAG / Corrective RAG / Agentic RAG 材料作为支撑。

**5. 输出格式要求**

- 总字数不少于 3000 字。
- 每个面试题单独成块，格式统一为：**题目 → 面试官在考什么 → 新手答法 → 高手思路 / 解决方法 → 落地要点**。
- 在文末附一个“检索来源说明”，列出你实际检索过的关键词和主要参考来源类型，便于追溯。
- 如果某个步骤在网上没有搜到足够有区分度的题目，明确说明“该步骤公开面试题较少，以下题目来自相关面试题库的交叉推断或通用工程追问”，不要虚构来源。
